Option, Either and Result for TypeScript

A small library that puts missing values and failures into the type signature, so the compiler can check that you handled them.

$npm i @universal-apps/ts-utils
Source on GitHub npm Blog post

Why

A function that can throw looks identical to one that cannot. Nothing in its signature tells the caller to expect a failure, so handling it is a matter of memory and convention.

With a Result the failure is part of the return type. The caller has to deal with both cases before the value can be used.

Before
function parsePort(input: string): number {
  const n = Number(input)
  if (Number.isNaN(n)) {
    throw new Error('not a number')
  }
  return n
}

// Nothing here says it can fail
const port = parsePort(raw)
After
function parsePort(input: string): Result<number> {
  const n = Number(input)
  return Number.isNaN(n)
    ? err(new Error('not a number'))
    : ok(n)
}

// The signature says it can fail
const port = matchResultF({
  ok: (n) => n,
  err: () => 3000,
})(parsePort(raw))

The types

Each type is a plain object, so values serialize and log without ceremony.

A value that may be absent. some(x) is { value: x }, none() is {}.

import { some, none, matchOptionF, type Option } from '@universal-apps/ts-utils'

const find = (id: number): Option<string> =>
  id === 1 ? some('Ada') : none()

const label = matchOptionF({
  some: (name) => `Hello, ${name}`,
  none: () => 'Unknown user',
})(find(1))
// "Hello, Ada"

An operation that succeeds with a value or fails with an error. Modeled on Rust's Result.

import { ok, err, matchResultF, type Result } from '@universal-apps/ts-utils'

const divide = (a: number, b: number): Result<number, Error> =>
  b === 0 ? err(new Error('divide by zero')) : ok(a / b)

matchResultF({
  ok: (value) => console.log(value),
  err: (e) => console.error(e.message),
})(divide(10, 4))
// 2.5

One of two outcomes, in the style of Scala's Either. right(x) is { value: x }, left(e) is { error: e }.

import { right, left, matchEitherF, type Either } from '@universal-apps/ts-utils'

const validate = (age: number): Either<Error, number> =>
  age >= 0 ? right(age) : left(new Error('age must be positive'))

const message = matchEitherF<Error, number, string, string>({
  right: (age) => `Age ${age}`,
  left: (e) => e.message,
})(validate(-1))
// "age must be positive"

A [result, error] pair for async code, so you can skip try/catch and branch on the error directly.

import { toTuple, type ResultTuple } from '@universal-apps/ts-utils'

const load = async (): Promise<ResultTuple<number>> => {
  try {
    return toTuple({ result: await fetchCount() })
  } catch (error) {
    return toTuple({ error: error as Error })
  }
}

const [count, error] = await load()
if (error) throw error
console.log(`Count is ${count}`)

API

ExportDescription
some(value)Builds an Option holding a value.
none()Builds an empty Option.
matchOption, matchOptionFMatch on some / none.
ok(value), err(error)Build a Result.
matchResult, matchResultFMatch on ok / err.
right(value), left(error)Build an Either.
matchEither, matchEitherFMatch on right / left.
toTuple({ result, error })Builds a ResultTuple. Throws if neither is given.

The F variants are curried: pass the matchers first, then the value. The plain variants take { result, matchers } in one call. Requires Node 16 or newer. No runtime dependencies. MIT licensed.
